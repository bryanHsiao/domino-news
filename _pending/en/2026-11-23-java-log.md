A scheduled Java agent runs at three in the morning, one run fails, and the next day you have no idea what happened. `System.out.println` goes nowhere you can read in a server agent; an exception was thrown, but nothing caught it and nothing recorded it.

[`Log`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_NOTESLOG_CLASS_JAVA.html) is for exactly this. The docs define it as "Enables you to record actions and errors that take place during a program's execution." — it records what you did and what went wrong, structured and timestamped. What makes it handy: the same `logAction` / `logError` API can write to four different destinations.

This covers creating a Log, what each destination fits, one server trap, and a few things to remember to close out.

---

## One object, four destinations

First [`session.createLog("Daily reconcile")`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_NOTESSESSION_CLASS_JAVA.html) to build a Log (the name you pass becomes `ProgramName`, identifying who's logging). Then **you must open a destination before logging** — four open methods for four destinations:

- `openNotesLog(server, dbfile)` — write to a specified Domino database. For collecting many agents' records centrally and querying them later with a view.
- `openMailLog(recipients, subject)` — open a new mail memo, the record goes into the email. Good for "mail the admin on failure."
- `openAgentLog()` — write to **the current agent's own log**. The docs: "Opens the agent log for the current agent." The least-effort choice for a scheduled agent — it shows up right in the agent's log in Designer / admin.
- `openFileLog(path)` — write to a local file.

```java
Log log = session.createLog("Daily reconcile");
log.openAgentLog();                       // into this agent's own log
log.logAction("Starting reconcile, 1,240 records");
// …run the logic…
log.logError(1, "Record 88 is missing a customer number");
log.close();
```

## One server trap: openFileLog

A very practical landmine: [`openAgentLog`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_OPENAGENTLOG_METHOD_JAVA.html) must run inside an agent (it fails outside one, or over remote IIOP), and **`openFileLog` returns an error when called on a server** — it's for a local client. It tests fine on your dev machine, then records nothing the moment it's a server agent, and openFileLog is very often why. On a server, record to openNotesLog or openAgentLog instead of a file.

## logAction / logError must be called explicitly

An easy misconception: NotesLog **does not log anything automatically**. The docs state plainly "actions and errors are not logged automatically. You must call logAction and logError explicitly." It isn't an interceptor and it won't catch exceptions for you — you call `logAction("did X")` and `logError(code, "failed at Y")` yourself, where it matters in the code. How many you logged is in `NumActions` / `NumErrors`.

To turn off one kind of logging (say, don't log actions in production, only errors), use the `IsLogActions` / `IsLogErrors` switches — note the property names are **`Is`-prefixed**, not `LogActions`.

## A few things to close out

- **openMailLog must be closed**: that memo is only actually sent on `close()` (or when the object is recycled). Forget to close and the mail never goes.
- **IsOverwriteFile only affects a file log**: it controls whether a file log overwrites or appends, and has no effect on a mail or database log.
- Log is a back-end handle — `recycle()` it when done; read it alongside error handling in [the Java NotesException piece](/domino-news/posts/java-notesexception/) — what `logError` records is often exactly the exception you caught.

## What about LotusScript and SSJS?

The same `Log`:

- **LotusScript**: `NotesLog`, with `OpenAgentLog` / `OpenNotesLog` / `LogAction` / `LogError` — same behavior, no recycle; the full usage is in [the NotesLog piece](/domino-news/posts/notes-log/).
- **SSJS / XPages**: `NotesLog`, same `session.createLog`; used less often in XPages (which has its own logging / server console), but available when a background job needs a record.
- **The Java-specific part** isn't the API (the methods are shared) — it's the setting: a scheduled / background Java agent has no interactive surface and `System.out` is hard to trace, so NotesLog's `openAgentLog` + `logAction` / `logError` is the most direct way to leave behind "what this run did and where it failed" — remembering that `logError` is yours to call; it won't catch your exception for you.
