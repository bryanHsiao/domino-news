你在 Java 比對兩個 Notes 使用者名稱:一個是登入者的 `session.getUserName()`,另一個是存在文件裡的簽核人欄位。明明是同一個人,`equals` 卻回 `false`。

原因是同一個人的名字,在不同地方形式不一樣。一邊可能是 canonical 的 `CN=John B Goode/O=Acme/C=US`,另一邊是 abbreviated 的 `John B Goode/Acme/US`,或只是 common 的 `John B Goode`。這三個字串長得完全不同,直接比當然不相等——但它們是同一個人。

處理這件事的是 [`Name`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_NOTESNAME_CLASS_JAVA.html) 類別,官方定義「Represents a user or server name.」。正解是:用它把兩邊正規化成同一形式再比。這篇講三種形式、怎麼正確比對、怎麼拆名字的各部分,以及它也能解析 internet 地址。

---

## 三種形式

用 [`session.createName(...)`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_NOTESSESSION_CLASS_JAVA.html) 把一個名字字串包成 Name 物件,就能要它的各種形式。官方的 [Representing a name using Java](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_REPRESENTING_A_NAME_JAVA.html) 列了三個:

- **Canonical**(`getCanonical`)——「A hierarchical name in canonical form.」每一段都有關鍵字和等號:`CN=John B Goode/OU=Sales/O=Acme/C=US`。這是最完整、最不會有歧義的形式。
- **Abbreviated**(`getAbbreviated`)——「A hierarchical name in abbreviated form.」去掉關鍵字、靠位置識別:`John B Goode/Sales/Acme/US`。
- **Common**(`getCommon`)——只有 CN= 那一段:`John B Goode`。

有個縮寫的眉角:class 頁明寫「The class won't abbreviate a name when the result would be ambiguous.」——縮寫結果會有歧義時,它不縮、直接回 canonical。例如 `CN=John B Goode/OU=East`,縮成 `John B Goode/East` 的話,`East` 會被誤認成組織(O=),所以它乾脆不縮。

## 正確比對:兩邊都正規化

比對的正解很簡單——**把兩邊都轉成同一形式再比**,通常用 canonical(最完整):

```java
Name a = session.createName(session.getUserName());   // 登入者
Name b = session.createName(doc.getItemValueString("Approver")); // 文件裡的
boolean same = a.getCanonical().equalsIgnoreCase(b.getCanonical());
a.recycle(); b.recycle();
```

兩邊都 `getCanonical()`,不管原本是縮寫還是 common,正規化之後就能比了。如果你只在意 common 名(例如顯示用),就兩邊 `getCommon()` 比——但要知道 common 名可能撞名(兩個不同組織各有一個 John B Goode),所以牽涉權限判斷時還是用 canonical。

## 拆出名字的各個部分

Name 也能把一個階層名拆成各段,這在「判斷某人在不在某個組織單位」時很有用。各段都是唯讀 getter:`getOrganization`(O=)、`getOrgUnit1` 到 `getOrgUnit4`(OU=,最多四層)、`getCountry`(C=)、`getCommon`(CN=)等。

要判斷某人是不是業務部的,**別用字串 `contains("Sales")`**——那會把名字裡剛好有 Sales 的人也算進去。用 `getOrgUnit1()` 之類精準比對那一段:

```java
Name n = session.createName(userName);
boolean inSales = "Sales".equalsIgnoreCase(n.getOrgUnit1());
```

## 它也解析 internet 地址

一個少人知道的能力:如果你傳進去的是符合 RFC 821/822 的字串,Name 會把它當 internet 地址解析。class 頁寫「A name that conforms to RFC 821 or RFC 822 is interpreted as an Internet address.」。傳 `"John B Goode" <jbg@us.acme.com>`,就能用 `getAddr821`(純地址)、`getAddr822LocalPart`(@ 前面)、`getAddr822Phrase`(引號裡的顯示名)把它拆開——不用自己寫 email 正則。

## 同類別在其他語言

同一個 `Name`:

- **LotusScript**:`NotesName`,`Canonical` / `Abbreviated` / `Common` 與各 name-part 屬性都在;名稱格式的完整說明見 [NotesName 格式那篇](/domino-news/posts/notesname-formats/)。
- **SSJS / XPages**:`NotesName`,一樣 `session.createName`;在 XPages 判斷登入者屬於哪個 OU、或顯示 common 名時常用。
- **Java 專屬的**不是 API(方法共用),而是這個「比對失敗」的 bug 在 Java 寫的 agent / managed bean 裡最常見——強型別不會提醒你「這兩個字串是不同形式的同一個人」,得自己記得先 `createName` 正規化再比。
