一個排程的 Java agent 半夜三點跑,某次失敗了,你隔天完全不知道發生什麼事。`System.out.println` 在 server agent 裡印到哪、你根本看不到;丟例外是丟了,但沒人接、沒留下紀錄。

[`Log`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_NOTESLOG_CLASS_JAVA.html) 就是幹這件事的。官方定義「Enables you to record actions and errors that take place during a program's execution.」——把「做了什麼」和「出了什麼錯」結構化、帶時間戳地記下來。它好用的地方是:同一套 `logAction` / `logError` 的 API,可以寫進四個不同的去處。

這篇講怎麼建一個 Log、四個去處各自適合什麼、一個 server 上的坑,以及幾個記得要做的收尾。

---

## 一個物件,四個去處

先 [`session.createLog("每日對帳")`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_NOTESSESSION_CLASS_JAVA.html) 建一個 Log(傳進去的名字會變成 `ProgramName`,標識是誰在記)。接著**記錄前一定要先 open 一個去處**,四個 open 方法對四個目的地:

- `openNotesLog(server, dbfile)`——寫進一個指定的 Domino 資料庫。要集中蒐集多個 agent 的紀錄、之後用 view 查,用這個。
- `openMailLog(recipients, subject)`——開一封新的 mail memo,記錄寫進信裡。適合「失敗就寄給管理員」。
- `openAgentLog()`——寫進**目前這個 agent 自己的 log**。官方「Opens the agent log for the current agent.」。排程 agent 最省事的選擇,直接在 Designer / admin 看 agent 的 log 就有。
- `openFileLog(path)`——寫進一個本地檔案。

```java
Log log = session.createLog("每日對帳");
log.openAgentLog();                       // 寫進這個 agent 自己的 log
log.logAction("開始對帳,共 1,240 筆");
// …跑邏輯…
log.logError(1, "第 88 筆缺客戶編號");
log.close();
```

## 一個 server 上的坑:openFileLog

這裡有個很實際的雷:[`openAgentLog`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_OPENAGENTLOG_METHOD_JAVA.html) 要在 agent 裡跑(非 agent、或遠端 IIOP 會失敗),而 **`openFileLog` 在 server 上呼叫會直接回 error**——它是給本機 client 用的。你在開發機測得好好的、一上 server agent 就記不出東西,很可能就是用了 openFileLog。server 上要落地成檔案以外的紀錄,用 openNotesLog 或 openAgentLog。

## logAction / logError 要自己呼叫

一個容易誤會的點:NotesLog **不會自動**幫你記什麼。官方明寫「actions and errors are not logged automatically. You must call logAction and logError explicitly.」。它不是攔截器、不會自動抓例外——你要在程式裡該記的地方,自己呼叫 `logAction("做了 X")`、`logError(code, "錯在 Y")`。記了幾筆可以從 `NumActions` / `NumErrors` 看。

要暫時關掉某一類記錄(例如正式環境不記 action、只記 error),用 `IsLogActions` / `IsLogErrors` 這兩個開關——注意屬性名是 **`Is` 前綴**的,不是 `LogActions`。

## 幾個收尾

- **openMailLog 一定要 close**:那封 memo 是在 `close()`(或物件被回收)時才真的寄出去。忘了 close,信不會寄。
- **IsOverwriteFile 只對 file log 有效**:它控制檔案記錄是覆蓋還是 append,對 mail / database log 沒作用。
- Log 是後端 handle,用完 `recycle()`;配合錯誤處理一起看 [Java 的 NotesException 那篇](/domino-news/posts/java-notesexception/)——`logError` 記的往往就是你 catch 到的那個 exception。

## 同類別在其他語言

同一個 `Log`:

- **LotusScript**:`NotesLog`,`OpenAgentLog` / `OpenNotesLog` / `LogAction` / `LogError` 都在,行為一致但不用 recycle;完整用法見 [NotesLog 那篇](/domino-news/posts/notes-log/)。
- **SSJS / XPages**:`NotesLog`,一樣 `session.createLog`;在 XPages 裡較少用(通常走 XPages 自己的 log / print to server console),但背景工作要留紀錄時可用。
- **Java 專屬的**不是 API(方法共用),而是場景:排程 / 背景的 Java agent 沒有互動介面,`System.out` 又難追,NotesLog 的 `openAgentLog` + `logAction` / `logError` 是把「這次跑了什麼、哪裡出錯」留下來最直接的方式——但記得 `logError` 要自己呼叫,它不會自動接住你的 exception。
