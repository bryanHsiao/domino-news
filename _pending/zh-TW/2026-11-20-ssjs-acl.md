在 XPages 跟 ACL 打交道,通常是兩件完全不同的事。

一是**查**:這個登入者是不是 Editor 以上?有沒有 `[Finance]` 這個角色?——用來決定一個「編輯」按鈕顯不顯示、一個 panel 要不要渲染。二是**改**:做一個管理介面,讓管理者在網頁上調別人的權限。

這兩件事的做法不一樣,而且第二件有個很多人卡住的地方:網頁上的使用者多半不是 Manager,根本改不動 ACL。這篇把兩種場景分清楚。

---

## 查權限:不必開 ACL 物件

做 UI 判斷時,你要的是「目前這個使用者」的權限,[`database`](https://help.hcl-software.com/dom_designer/14.5.1/reference/r_domino_Database.html) 上就有現成的查詢方法,不必開 ACL 物件:

- `database.getCurrentAccessLevel()`——官方「The current user's access level to a database.」。拿來跟 `NotesACLEntry.LEVEL_EDITOR` 之類的常數比:

```javascript
// 某個「編輯」按鈕的 rendered 屬性
database.getCurrentAccessLevel() >= NotesACLEntry.LEVEL_EDITOR
```

- `database.queryAccess(name)`——官方「Returns a person's, group's, or server's current access level to a database.」。查「別人」的權限用這個。
- `database.queryAccessRoles(name)`——官方「Returns the roles of a person, group, or server in a database.」。做角色門禁(某區塊只給有 `[Finance]` 角色的人)用它最乾淨,回來是這個人擁有的角色清單,比「開 ACL → getEntry → isRoleEnabled」少繞好幾步:

```javascript
// 只給 Finance 角色的人看
var roles = database.queryAccessRoles(session.getEffectiveUserName());
roles.indexOf("[Finance]") >= 0
```

## 改權限:為什麼一定要 sessionAsSigner

要在 XPages 做一個「調整別人權限」的管理介面,就得開 [`NotesACL`](https://help.hcl-software.com/dom_designer/14.5.1/reference/r_domino_ACL.html) 物件來改——`getACL`、`createACLEntry` / `getEntry` 改 level、`addRole`,最後 `save`。save 的規則跟後端一樣,官方「If you don't call save before closing a database, the changes you've made to its ACL are lost.」,改完沒 save 就白做。

但這裡有個權限的死結:**改 ACL 這個動作本身需要 Manager 權限**,而網頁上點進來的使用者通常只有 Author / Editor。用預設的 `database`(= 目前使用者身分)去 `getACL().save()`,會因為權限不足而失敗。

解法是提權:透過 [`sessionAsSigner`](https://help.hcl-software.com/dom_designer/14.5.1/reference/r_wpdr_globals_r.html) 以「這個 XPage 設計元件的簽署者」身分取得資料庫,再改它的 ACL——前提是那個簽署者在 ACL 裡有 Manager 權:

```javascript
var db = sessionAsSigner.getDatabase(database.getServer(), database.getFilePath());
var acl = db.getACL();
acl.getEntry("CN=John/O=Acme").setLevel(NotesACLEntry.LEVEL_EDITOR);
acl.save();
```

這個提權機制的細節、以及它的安全邊界,見 [XPages 的 sessionAsSigner 那篇](/domino-news/posts/xpages-sessionassigner/)。ACL 修改本身(roles 兩層、各種 entry 操作)的完整說明,見 [Java 改 ACL 那篇](/domino-news/posts/java-acl/)——API 一樣,只差 XPages 要自己提權。

## 一句話分流

- **要做 UI 條件(顯不顯示、能不能編輯)** → 查就好:`getCurrentAccessLevel()` / `queryAccessRoles()`,不開 ACL 物件、不提權。
- **要真的改別人的權限** → 開 ACL 物件改 + `save`,而且繞 `sessionAsSigner` 提權。

## 同類別在其他語言

同一組 `ACL` / `ACLEntry`:

- **LotusScript**:`NotesACL` / `NotesACLEntry`,`QueryAccess` / `GetACL` / `Save` 都在;完整用法見 [NotesACLEntry 那篇](/domino-news/posts/notes-acl-entry/)。
- **Java**:`ACL` / `ACLEntry`,API 相同;ACL 修改(save、roles 兩層)的深講見 [Java 改 ACL 那篇](/domino-news/posts/java-acl/)。
- **SSJS 專屬的**不是 API(方法共用),而是**在 XPages 的兩種用法**:查權限走 `database` 的 `getCurrentAccessLevel` / `queryAccessRoles` 捷徑做 `rendered` 條件;改權限則因為 web 使用者多半非 Manager,一定要繞 `sessionAsSigner` 提權才改得動。
