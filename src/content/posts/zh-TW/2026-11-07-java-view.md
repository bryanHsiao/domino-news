你有一個 view,裡面 5 萬筆訂單。要做一份報表,列出訂單編號、客戶、金額三欄。直覺的寫法:取 view、`getFirstDocument()` 一路 `getNextDocument()`,每份文件 `getItemValueString("OrderNo")`…

在 Java 這樣寫,等於**開了 5 萬份文件**——每一次 `getNextDocument()` 都是把整份 `Document` 從後端拉出來,你用完還得 `recycle()`。但那三欄的值,**view 的每一列本來就算好、擺在那裡了**。

view 的一列就是一個 `ViewEntry`,它身上帶著這列各欄的值;`getColumnValues()` 一次把整列的欄位值拿出來,**一份文件都不用開**。這篇就講:在 Java 怎麼取到 view、怎麼用 entry 而不是 document 來讀、怎麼依 key 查,以及迭代時要先關掉的一個開關。

---

## 先把 view 拿到手:getView 的兩個小坑

`database.getView(name)` 取一個 [`View`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_NOTESVIEW_CLASS_JAVA.html)——官方定義很直白:「Represents a view **or folder** of a database」。兩個實務上會絆到的點:

1. **它找的是「view 或 folder」。** 同一個 `getView("Inbox")` 可能拿回的是一個 folder、不是 view。如果你的邏輯只對 view 成立,拿到後用 `isFolder()` 確認一下。
2. **name 或 alias 都行,但別混寫。** 參數不分大小寫,吃顯示名稱、也吃 alias;但官方明講「do not combine the view name and an alias」——別把「名稱|alias」那種帶管線符號的設計值整串丟進去。

還有一點值得跟 [Java 取 Database handle 那篇](/domino-news/posts/java-database/) 對照:`getDatabase` 有個「開不到也回一個空殼(`isOpen` 是 false)」的陷阱;`getView` **沒有**那種 createonfail 空殼——官方只說它回「name 或 alias 相符的那個」。拿到就用,但還是順手 guard 一下再往下。

## 讀一列的欄位:用 ViewEntry,不要開 Document

這是 Java 讀 view 最該改的習慣。一列 = 一個 [`ViewEntry`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_NOTESVIEWENTRY_CLASS_JAVA.html),官方定義就是「Represents a view entry. A view entry describes a **row** in a view.」。它的 `getColumnValues()` 一次回傳**這一列所有欄位的值**(一個 `Vector`),順序就是 view 欄位的順序:

```java
ViewEntryCollection col = view.getAllEntries();
ViewEntry entry = col.getFirstEntry();
while (entry != null) {
    Vector<?> cols = entry.getColumnValues();   // 整列欄位值,一份文件都沒開
    System.out.println(cols.elementAt(0) + " / " + cols.elementAt(2));

    ViewEntry next = col.getNextEntry(entry);   // 先拿下一個
    entry.recycle();                            // 再回收當前
    entry = next;
}
```

跟「每列 `getNextDocument()` 再 `getItemValue`」比,差距不是一點點:前者只動 view 的索引、欄位值早就在索引裡;後者每一列都把整份文件從後端拉出來。做報表、做清單、做匯出,**能用 entry 讀就別開 document**。

什麼時候還是得開 document?當你要的值**不在任何 view 欄位裡**(欄位沒顯示它,或你要的是原始 item 值、而不是欄位算出來的顯示值)。這時再 `entry.getDocument()` 拿文件——那是「需要才開」,不是預設每列都開。

## 依 key 查:getAllEntriesByKey

view 已經依欄位排序、建好索引,拿它「查表」比 `FTSearch` 或整表掃快得多。[`getAllEntriesByKey`](https://help.hcl-software.com/dom_designer/14.5.1/basic/H_GETALLENTRIESBYKEY_METHOD_JAVA.html) 依 key 比對已排序的欄位,回一個 `ViewEntryCollection`:

```java
Vector<String> keys = new Vector<>();
keys.add("ACME");            // 比對第一個排序欄
ViewEntryCollection hits = view.getAllEntriesByKey(keys, true);  // true = 精確
```

官方把參數講得很清楚:`key` 可以是單一值(比對第一個排序欄)或一個 `Vector`(逐欄比對);最後那個 `boolean exact`——**給 `true` 是精確比對;給 `false` 或省略,走部分比對**(前綴符合就算中)。要一筆就 `getEntryByKey`,要全部符合的就 `getAllEntriesByKey`。分類 view 依 key 查的完整脈絡,[by-key 那篇](/domino-news/posts/by-key-lookup-categorized-views/) 從 LS 角度講過,Java 走的是同一套索引。

## 迭代時:先 setAutoUpdate(false)

view 預設會「自動更新」——當別的程序在你跑迴圈的同時改了底層文件,view 索引會跟著動,你的 `getNextEntry` 可能就跳掉、重複、或指到一個已經變了的位置。要一段穩定的快照,迭代前把它關掉:

```java
view.setAutoUpdate(false);   // 這段迴圈期間,view 不要在我腳下變
```

跑完該收的還是要收。view、entry、collection 都是後端 handle,用完 `recycle()`;而且**別在還握著 entry 的時候就把 view recycle 掉**——parent 收了,底下的 entry 跟著死。迴圈裡逐一回收的完整紀律,在 [改寫成 Java 後記憶體爆掉](/domino-news/posts/java-collection-iteration/) 和 [Java recycle 那篇](/domino-news/posts/java-recycle-memory/) 講得更細;這裡只留一句:**先取 next、再 recycle 當前**(上面範例就是這個順序)。

## 同類別在其他語言

同一個 view,三種語言的 class:

- **LotusScript**:`NotesView`,搭 `NotesViewEntry` / `NotesViewEntryCollection` / `NotesViewNavigator`;沒有 `recycle` 這道功課。
- **SSJS / XPages**:`NotesView`(或直接 `View`),一樣有 `getAllEntriesByKey`、`ViewEntry.getColumnValues`;生命週期由 XPages request 管,不用自己 recycle。
- **Java 專屬的**,正是這篇:用 entry 讀欄位省掉大量 document 開啟,但 entry / collection / view 的 recycle 鏈要自己顧——細節見 [改寫成 Java 後記憶體爆掉](/domino-news/posts/java-collection-iteration/)。
